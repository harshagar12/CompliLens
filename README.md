# CompliLens

**AI-Assisted Automated Legal Metrology Compliance and Inspection System**  
*Built for Legal Metrology (Packaged Commodities) Rules, 2011 (LMPC).*

---

## 📖 The Problem Statement
Under the Legal Metrology (Packaged Commodities) Rules, 2011 (LMPC), manufacturers are mandated to display specific statutory declarations on consumer goods—such as the Maximum Retail Price (MRP), Net Quantity, Manufacturer Name and Address, Customer Care details, and Manufacture/Expiry Dates. 

Currently, Legal Metrology Officers inspect these packaged commodities manually. This process is deeply flawed because:
- **Time-Consuming & Fatigue-Inducing**: Analyzing fine print, low-contrast text, and faded dot-matrix inkjet prints across thousands of products drains regulatory resources.
- **Prone to Human Error**: Missing minute omissions or changes (like a dropped allergen warning or a slight reduction in net weight) is highly likely during manual review.
- **Lack of Historical Tracking (Reactive, not Proactive)**: It is nearly impossible to track the historical compliance of a product line across multiple packaging revisions. Manufacturers often change packaging slightly over years, silently introducing non-compliance or shrinkflation, which manual spot-checks miss.

---

## 💡 The Solution Strategy
**CompliLens** is a comprehensive, AI-powered compliance platform designed specifically for regulatory officers and compliance auditors. It automates the extraction of statutory declarations from packaging artworks and rigorously verifies them against a deterministic LMPC rules engine.

**Crucially, CompliLens NEVER uses LLMs to make regulatory decisions (which can hallucinate).**
Instead, the architecture strictly decouples perception from evaluation:
1. **AI for Perception**: Machine learning models (RapidOCR / Gemini) are used strictly to "read" the label and extract text and bounding boxes.
2. **Deterministic Rules for Evaluation**: The actual compliance verdict (`PASS`/`FAIL`) is generated by a **deterministic, version-controlled Rules Engine** (written in JSON) that evaluates the extracted text mathematically and directly cites the relevant LMPC statutes.

## 🔍 Deep Dive: Core Features & Minute Details

### 1. Inspection Studio (Single Label Analysis)
The Inspection Studio is the core workspace for auditing a single packaged commodity.

* **Image Upload & Initialization**: The officer uploads a high-resolution image of the packaging. The frontend Next.js client uploads this to the FastAPI backend as a `multipart/form-data` payload. The image is stored locally in the `data/uploads` directory, and a unique UUID tracking ID is generated and returned to the client.
* **Step-by-Step OCR Data Flow**:
  1. **Preprocessing (Deskewing & CLAHE)**: 
     - **Deskewing**: Often, officers take photos at slight angles. The preprocessing pipeline uses OpenCV to detect the angle of the text lines using Canny edge detection and Probabilistic Hough Transforms. It then calculates the skew angle and performs an affine transformation to rotate the image so that the text is perfectly horizontal. This prevents the OCR engine from misreading slanted text.
     - **CLAHE (Contrast Limited Adaptive Histogram Equalization)**: Unlike standard brightness adjustments which wash out images, CLAHE divides the image into small 8x8 pixel tiles and enhances contrast locally within each tile. It is highly effective at bringing out faded, low-contrast dot-matrix inkjet text (often used for Expiry Dates and MRP) from dark backgrounds while preventing over-amplification of noise.
  2. **AI-Powered OCR Extraction**: The preprocessed image is fed into an OCR engine. 
     - **Local AI Mechanics (RapidOCR)**: RapidOCR is a local, CPU-bound OCR engine. Despite running locally, it is heavily powered by deep learning AI models compiled into the highly optimized ONNX format. It operates in two stages:
       - *Text Detection (DBNet)*: A Differentiable Binarization network scans the image and draws polygons around regions that look like text.
       - *Text Recognition (CRNN)*: A Convolutional Recurrent Neural Network (with BiLSTM layers) reads the pixels inside each detected polygon and converts them into string characters.
     - **Output**: The OCR engine returns an array of "tokens", where each token consists of the raw text and its **Bounding Box** `(x_min, y_min, width, height)`—the exact pixel coordinates of where that text exists on the original image.
  3. **Spatial Classification**: The backend groups the text tokens into vertical columns (to prevent reading across distinct label panels) and uses regex and layout heuristics to classify tokens into LMPC statutory fields (e.g., `net_quantity`, `mrp`, `manufacturer_name_address`).
  4. **Bounding Box Extraction & Cropping**: For every classified field, the backend uses the extracted `(x, y, w, h)` bounding box coordinates to literally crop out that specific snippet from the original uploaded image using NumPy array slicing (`image[y:y+h, x:x+w]`). These crops are saved to disk and served via static routes.
* **Human-in-the-Loop Review**: The frontend receives the classified fields alongside their cropped image snippets. The officer views the crops side-by-side with the extracted text. Because they can see the exact visual evidence (the bounding box crop), they can confidently verify or correct the OCR text, effectively acting as an auditor of the AI.
* **Deterministic Evaluation**: Once confirmed, the data is pushed to the Rules Engine. The engine runs mathematical checks (e.g., verifying if the MRP string matches a required regex format like "inclusive of all taxes") and outputs a final compliance verdict.

### 2. Variance Studio (Multi-Label Analysis)
Allows officers to upload 2 to 5 different historical packaging revisions of the same product to detect silent, illegal changes over time.

* **Parallel Batch Extraction**: To prevent massive delays, all uploaded images bypass Python's Global Interpreter Lock (GIL) and are processed through the OCR pipeline in parallel using `asyncio.gather` and `concurrent.futures.ProcessPoolExecutor`. A `fast_mode` flag disables secondary OCR passes, cutting extraction time for 3 images from ~75 seconds down to ~20 seconds.
* **Auto-Sort by Manufacture Date**: The system extracts the manufacture dates (e.g., `09/26`, `MFG: SEP 2026`) and uses a robust negative-lookahead regex engine to parse them into `(Year, Month)` tuples, automatically sorting the labels in chronological ascending order (oldest to newest).
* **Shrinkflation Detection**: The backend algorithmically compares the extracted `mrp` and `net_quantity` across the chronologically sorted revisions. It parses out the numerical values and units, calculates the price-per-gram for each revision, and if it detects that the physical quantity has decreased (e.g., 200g to 180g) but the unit price remains the same or increases, it triggers a severe **Shrinkflation Alert**.
* **Formulation Shift Analysis (Semantic Diffing)**: An LLM agent analyzes the non-statutory text (Ingredients and Allergens). Because ingredients are often re-ordered or re-phrased (e.g., "Raising Agents (500(i))" vs "Sodium Bicarbonate"), a strict string comparison would fail. The LLM semantically diffs the lists to find exact swapped ingredients, silently dropped allergens, or altered percentages, highlighting these critical shifts for the user.

### 3. Product History Dashboard
A centralized hub for analyzing the lifecycle of a single registered product across multiple years and inspections.

* **Longitudinal Compliance Tracking**: Displays a timeline graph of every inspection conducted on a specific product (e.g., "Crunchy Nut Cookies"). All past inspection verdicts, extracted fields, and PDF reports are pulled from the PostgreSQL database.
* **Metric Aggregation**: Charts how the product's compliance score has evolved, providing officers with a clear visual indicator of whether a manufacturer is improving their compliance standards or degrading them across subsequent packaging releases. It helps identify repeat offenders on a per-product basis.

### 4. Manufacturer Audit Dashboard
A high-level macroscopic view for auditing a manufacturer's entire corporate portfolio.

* **Portfolio-Wide Analytics**: Aggregates compliance statistics across all products owned by a specific manufacturer (e.g., pulling all inspection data where `manufacturer_name_address` matches "NutriBite Foods").
* **Systemic Non-Compliance Detection**: Identifies trends in rule violations. For example, the dashboard can reveal if a manufacturer is systematically omitting customer care emails across 80% of their product lines. This empowers regulatory officers to issue targeted, company-wide legal notices rather than playing whack-a-mole with isolated product warnings.

### 5. Audit Dossier Generation
* Once an inspection is complete, CompliLens compiles the extracted text, the verified bounding-box crops, and the exact legal statute citations into a comprehensive HTML report.
* Using Gotenberg (a headless Chromium Docker container), this HTML is converted into a highly polished, tamper-proof, downloadable PDF Audit Dossier that serves as physical evidence for official legal notices.

## 🛠️ Detailed Technology Stack

### Backend Architecture
- **Python 3.11+ & FastAPI**: Provides a high-performance, asynchronous REST API capable of handling heavy concurrent image uploads.
- **Uvicorn**: An ASGI web server implementation used to run the FastAPI application efficiently.
- **Pydantic**: Used for strict type enforcement and data validation of incoming/outgoing JSON payloads.
- **PostgreSQL**: Relational database used to store all product history, inspection records, and manufacturer portfolios.
- **ONNX Runtime & RapidOCR**: Executes deep learning models locally on the CPU for high-speed text perception without needing cloud GPUs.
- **Google Gemini 1.5 Flash**: Accessed via API for fallback OCR capabilities and complex semantic formulation diffing (understanding ingredient synonyms).
- **OpenCV & NumPy**: Used heavily in the `preprocessing.py` pipeline to perform matrix math for CLAHE, image rotations (deskewing), and bounding box cropping.

### Frontend Dashboard
- **Next.js (App Router) & React**: Modern, server-rendered frontend framework providing lightning-fast navigation and seamless state management across the complex review dashboards.
- **TailwindCSS**: Utility-first CSS framework for building the highly responsive, modern, and accessible user interface.
- **TypeScript**: Enforces strict typing for all API payloads and React props, ensuring the frontend never crashes due to unexpected data shapes from the AI pipeline.

### PDF Infrastructure & Containerization
- **Docker & Docker Compose**: Orchestrates the entire multi-container stack (Database, Backend, Frontend, and Gotenberg).
- **Gotenberg**: A Docker-powered stateless API for PDF generation using a headless Chromium browser. It guarantees pixel-perfect rendering of the HTML audit reports.

## 🚀 Comprehensive Setup & Installation

You have two choices for running CompliLens: **Fully Dockerized** (Recommended for production/demos) or **Local Development** (Recommended if you want to modify code and see instant hot-reloads).

### Prerequisites
- **Docker and Docker Compose** installed on your system.
- **Node.js 18+ and npm** installed on your system (for Local Dev).
- **Python 3.11+** installed on your system (for Local Dev).
- A valid **Google Gemini API Key** (Required for semantic formulation analysis and OCR fallback).

### Step 1. Clone the Repository
Open your terminal and clone the repository to your local machine:
```bash
git clone https://github.com/harshagar12/CompliLens.git
cd compli-lens
```

### Step 2. Configure Environment Variables
You must set your Gemini API key so the semantic LLM diffing and OCR fallbacks can function.
Navigate to the `backend/` directory and create a `.env` file:
```bash
cd backend
echo "GEMINI_API_KEY=your_actual_google_gemini_api_key_here" > .env
```
*(If running via Docker, edit the `docker-compose.yml` to inject this key, or create a global `.env` file in the root directory).*

---

### Option A: Fully Dockerized Setup (Easiest)

This spins up the Database, Backend, Frontend, and Gotenberg PDF engine automatically.

```bash
# From the root compli-lens directory:
docker-compose up --build -d
```
- The **Frontend Dashboard** will be live at: `http://localhost:3000`
- The **Backend API Docs** will be live at: `http://localhost:8000/docs`
- To stop the system, run: `docker-compose down`

---

### Option B: Local Development Setup (For Modifying Code)

If you want to edit the code and have the servers hot-reload automatically:

#### 1. Start the PostgreSQL Database & Gotenberg (via Docker)
Even in local dev, you need the database and PDF engine running:
```bash
# Start ONLY the DB and Gotenberg from the docker-compose stack
docker-compose up -d db gotenberg
```

#### 2. Start the Backend Server (FastAPI)
CompliLens uses a virtual environment to isolate its Python dependencies.
```bash
cd backend
python -m venv .venv

# Activate the virtual environment
# On Windows:
.\.venv\Scripts\activate
# On Mac/Linux:
# source .venv/bin/activate

# Install all required Python packages
pip install -r requirements.txt

# Boot up the backend server using Uvicorn with auto-reloading enabled
python -m uvicorn main:app --reload --port 8000
```
*The backend API is now running on `http://127.0.0.1:8000`.*

#### 3. Start the Frontend Dashboard (Next.js)
Open a **new, separate terminal window** (leave the backend running), and navigate to the frontend directory:
```bash
cd compli-lens/frontend

# Install all required Node.js dependencies
npm install

# Start the Next.js development server
npm run dev
```
*The UI is now active! Open your browser and navigate to `http://localhost:3000` to access the CompliLens dashboard.*

## ⚙️ Scaling the Law (Modifying the Rules Engine)
To ensure the system remains robust as laws and regulations change, every LMPC rule in CompliLens is a declarative JSON file located in `backend/engine/rules/`. 

**You do not need to rewrite Python code to add new legal checks.** 
To add a new rule, simply create a new JSON file specifying the `required_field` and the `validation_condition`. 
For example, to enforce that an MRP must always contain the phrase "inclusive of all taxes", the JSON defines:
```json
"validation_condition": { 
  "op": "regex_match", 
  "pattern": "(?i)inclusive\\s+of\\s+all\\s+taxes" 
}
```
The engine dynamically parses this directory on startup and applies the new legal checks to all future inspections automatically!
